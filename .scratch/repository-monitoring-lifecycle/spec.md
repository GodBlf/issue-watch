# 监控仓库移除与重新加入

Status: ready-for-agent

## Problem Statement

使用者移除监控仓库后，旧通知仍持续发送；几天后重新加入，又从旧进度补抓停监期间的新建 Issue，产生大量手机通知。配置已保存也不能说明停止发送已生效。

## Solution

移除终止监控周期，取消该仓库未发送及重试通知，并停止共享 Issue 跟踪及其积压。重新加入开启新周期，仅通知加入生效后创建的 Issue。其他仓库和设置保持不变；已开始的 QQ 请求可能送达。明确区分配置已保存与移除已生效。

## User Stories

1. As an 管理员, I want 移除仓库后停止新建 Issue 通知, so that 手机不再持续响通知。
2. As an 管理员, I want 取消该仓库待发送积压, so that 移除不只是暂停抓取。
3. As an 管理员, I want 取消该仓库等待重试的投递, so that 失败通知不会稍后恢复发送。
4. As an 管理员, I want 同时停止该仓库的共享 Issue 跟踪, so that 移除覆盖仓库所有通知来源。
5. As an 管理员, I want 跟踪的未发送动态同时取消, so that 旧动态不会继续推送。
6. As an 管理员, I want 重新加入从生效时间开始, so that 停监期间的 Issue 不会补发。
7. As an 管理员, I want 重新加入不恢复旧跟踪或旧投递, so that 重新开始不会复活历史积压。
8. As an 广播订阅者, I want 已发送记录保留, so that 历史 Issue 不会重复通知。
9. As an 广播订阅者, I want 其他仓库通知继续正常发送, so that 单仓库取消不影响其他监控。
10. As an 管理员, I want 移除作用于全部广播订阅者, so that 共享仓库状态一致。
11. As an 管理员, I want 看见已保存和已生效的区别, so that 明确什么时候停止新发送。
12. As an 管理员, I want 队列统计及时排除取消投递, so that 页面不会误报积压。
13. As an 管理员, I want 在途请求的真实成功结果保留, so that 无法撤回的发送仍有准确记录。
14. As an 管理员, I want 升级保留配置内仓库的进度及正常积压, so that 修复不会丢弃其他仓库通知。
15. As an 管理员, I want 重启执行最终配置对账, so that 停机期间移除仓库也能停止其旧队列。
16. As an 管理员, I want 普通重启和大小写编辑保留监控周期, so that 日常操作不会重设监控起点。
17. As an 管理员, I want 旧 GitHub 请求不能污染新周期, so that 快速移除再加入也不会补发。
18. As an 管理员, I want 配置接受失败整体回滚, so that 不会出现部分仓库已取消但配置未生效。

## Implementation Decisions

- 仓库存储持久化启用状态和监控周期身份；启动和热加载共用事务对账。保留仓库进度不动，移除取消积压及跟踪，重新加入更新基线并清空旧游标。
- GitHub 抓取携带周期身份，入库及更新游标时校验启用状态和身份；过期响应丢弃。跟踪停止后旧响应也不能入队，新增跟踪的在途验证不能跨周期生效。
- 广播和跟踪发送开始通过 SQLite 事务领取投递，与移除事务确定先后。网络请求不占用数据库锁。已开始投递可完成，移除后失败不重试，成功准确记录。
- 启动恢复崩溃遗留的在途状态；恢复只由启动路径执行，普通打开数据库连接不能触发恢复。沿用既有至少一次投递限制，不保证跨 QQ 和数据库的恰好一次。
- 取消批次立即跳过，只为实际发送节流；等待过程中检查取消，避免被历史积压拖延。
- 热加载接受即持久化停止状态并更新仓库健康信息、队列和管理状态，不等待主循环完成整批工作。页面说明重新加入不会补发或恢复跟踪。
- 首次升级保留当前配置内旧仓库的进度；配置外仓库停用并取消积压。停机时移除又加回、且服务未观察中间状态时，按最终配置视为连续监控。
- 已核对线上 revision 与最新主分支一致，修复基于包含共享 Issue 跟踪的版本。

## Testing Decisions

- 已确认的主要测试边界为配置接受到 GitHub 发现、真实 SQLite、QQ 投递的公共链路。只替换外部 GitHub/QQ 和时钟；不模拟内部存储。
- 固定 3 号移除、7 号加入，断言停监期间 Issue 不发送、加入后 Issue 正常发送。
- 通过可控外部请求模拟移除和快速加入，断言旧响应不入库、不污染游标，旧跟踪不复活。
- 验证发送前取消、在途成功与失败、重试取消、多订阅和其他仓库不受影响，大批取消不消耗逐条节流等待。
- 沿用配置热加载、广播和共享跟踪集成测试风格；覆盖启动迁移、崩溃恢复、回滚和大小写身份。
- 管理页面与健康公共接口验证状态及时反映，浏览器测试检查影响范围提示。完整套件和流水线验证部署迁移及容器启动。

## Out of Scope

历史补发入口、专门的操作事件日志、QQ 已开始请求撤回、跨系统恰好一次保证、其他仓库配置或订阅变更。

## Further Notes

升级按现有停服务及数据库备份流程进行。启动后验收失败不自动恢复旧数据库。使用者已授权提交 PR、合并及触发流水线；PR 检查通过并完成代码审查后合并。
