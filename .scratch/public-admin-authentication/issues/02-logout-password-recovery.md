# 02: 退出登录与 SSH 密码恢复

**What to build:** 管理员能在浏览器退出当前会话，也能在忘记密码或怀疑凭据泄露时通过 SSH 重置密码并立即撤销全部设备的登录。页面遇到失效会话时明确引导重新登录，不把未授权操作显示为保存成功。

**Blocked by:** 01 — 管理员登录与一年会话。

Status: ready-for-agent

- [ ] 管理界面提供退出操作，服务端撤销当前会话并清除 Cookie；复制退出前的 Cookie 再请求管理 API 必须失败，不能仅依赖客户端删除 Cookie。
- [ ] 两个设备分别登录后，一个设备退出不影响另一设备；撤销状态重启后仍有效。
- [ ] 提供通过 SSH 执行的密码重置入口，安全输入新密码，不依赖旧密码、邮箱或浏览器登录；密码及会话凭据不进入命令行参数、shell 历史、日志或版本库。
- [ ] 重置密码和撤销全部会话原子生效。运行中的服务无需重启即可拒绝旧密码及全部旧会话，包括已打开页面随后发出的请求；新密码可建立新会话。
- [ ] 并发登录与密码重置协调，不能在重置成功后留下通过旧密码获得的有效会话；重置失败不产生部分凭据修改或虚假的成功反馈。
- [ ] 管理页面请求收到 401 时明确提示重新登录，不显示保存成功，不盲目重放业务写请求；已提交但结果未知的操作提示刷新核实。
- [ ] 不新增浏览器设备会话列表或逐设备远程撤销界面；本期只提供当前会话退出和 SSH 全量撤销。
- [ ] 通过现有 HTTP 集成边界和真实持久化状态验证退出、旧 Cookie 重放、多设备互不影响、服务运行时重置、旧密码失败、全部旧会话失效及重启后保持失效。
- [ ] 沿用现有页面 DOM/网络测试模式验证退出及失效会话提示，并覆盖密码重置与并发登录的可观察结果，不断言内部表结构。
- [ ] 提供忘记密码、凭据疑似泄露及手动恢复旧数据库后的恢复说明；恢复旧数据库可能恢复旧会话，重新开放公网前必须重置密码并撤销全部会话。保留现有数据库恢复由人工决定的边界。
