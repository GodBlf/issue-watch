# 03: 公网登录防护与 HTTPS 同源校验

**What to build:** 管理员在公网 HTTPS 来源下正常登录和管理，攻击者不能通过暴力猜测、跨站请求或伪造代理信息绕过访问控制。限制触发后有明确反馈且能自动恢复，不永久锁死唯一管理员。

**Blocked by:** 01 — 管理员登录与一年会话。

Status: ready-for-agent

- [ ] 将管理写操作的允许来源从仅回环 HTTP 适配为显式配置的公网 HTTPS Origin，部署 IP、端口和 Origin 保持一致，不在业务逻辑中硬编码服务器 IP。
- [ ] 登录和全部管理写操作具有跨站请求防护；为后续退出操作提供相同的统一校验机制，不能依赖 SameSite 或固定管理请求头作为唯一保护。
- [ ] 错误协议、端口、Origin、跨站上下文及伪造 Host 不得扩大允许范围；不开放任意来源的带凭据 CORS，不通过放松校验解决代理兼容问题。
- [ ] 登录尝试限制同时覆盖单来源和全局总量，控制密码哈希计算资源；使用可恢复的时间窗口或退避，具体阈值记录在运维说明中，不永久锁死管理员。
- [ ] 来源及协议识别仅信任明确配置的代理边界；任意客户端伪造转发头不能绕过限流、认证或内部健康检查隔离。
- [ ] 限流返回 429 和可理解的重试提示；已认证但不符合跨站写入保护的请求返回 403。登录页区分输入错误、限流和服务异常，错误响应不泄露秘密。
- [ ] 对外认证响应不缓存敏感数据；密码与会话不进入 URL、应用日志或错误详情，认证失败不能触发匿名降级。
- [ ] 沿用 HTTP 集成测试验证合法 HTTPS Origin 下正常操作、跨站登录和管理写入失败、错误协议及端口失败，以及伪造 Host 和转发头无法绕过防护。
- [ ] 用可控时间及来源测试单来源限流、全局限流、等待恢复和哈希计算资源边界；不依赖真实公网攻击或长时间等待。
- [ ] 为退出操作提供同一防护的可复用测试场景；本工单可在 02 尚未完成时独立验证登录与既有管理写入，最终退出跨站行为在公网验收中确认。
- [ ] 更新可信代理、外部 Origin、限流及错误排查说明；保留现有业务管理请求正常行为，不新增独立于 QQ 追踪命令权限的隐式授权。
