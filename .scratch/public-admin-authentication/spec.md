# 公网 HTTPS 管理入口与单管理员登录

Status: ready-for-agent

## Problem Statement

管理员目前必须建立 SSH 本地端口转发才能打开管理界面，无法直接通过浏览器访问服务器。现有服务没有登录或会话体系，管理写操作的回环同源校验只适用于 SSH 隧道场景；直接开放监听既会暴露管理数据，也不能正常执行现有写操作。

管理员希望使用服务器 IP 直接管理监控仓库、通知目标、仓库订阅、Issue 追踪和追踪命令权限，并在自己的浏览器长期保持登录，同时保留忘记密码和凭据泄露时的恢复能力。

## Solution

提供 `https://172.197.176.142/` 管理入口，以本地单管理员密码登录。全部管理页面及管理 API 均受身份认证保护，浏览器通过安全 Cookie 保存会话；每次登录固定有效一年，重启后保留，允许多个设备分别登录。退出撤销当前会话，通过 SSH 重置密码时撤销全部会话。

公网 443 由 HTTPS 代理提供管理服务，代理转发到现有回环服务；8081 不直接对公网开放。公网 80 仅提供证书验证路径。通过自动签发与续期的可信 IP 证书避免浏览器证书警告，不要求域名，不使用额外子路径。

## User Stories

1. As an 管理员, I want 直接打开服务器的 HTTPS IP 地址, so that 无需每次先建立 SSH 隧道。
2. As an 管理员, I want 使用默认 HTTPS 端口和根路径, so that 不必记忆额外端口和路径前缀。
3. As an 管理员, I want 浏览器信任服务器证书, so that 无需忽略证书警告。
4. As an 管理员, I want 在登录页输入本地管理员密码, so that 只有知道密码的人能够使用管理功能。
5. As an 管理员, I want 无需注册账户或绑定第三方身份, so that 单人管理保持简单。
6. As an 管理员, I want 通过 SSH 安全设置初始密码, so that 新部署没有可猜测的默认凭据。
7. As an 管理员, I want 未设置密码时管理功能保持关闭, so that 初始化过程不会暴露管理权限。
8. As an 管理员, I want 错误密码得到明确但不泄露内部信息的提示, so that 能纠正输入。
9. As an 管理员, I want 连续登录尝试受到限制, so that 公网攻击者难以暴力猜测密码。
10. As an 管理员, I want 登录成功后进入现有管理界面, so that 继续使用熟悉的管理功能。
11. As an 管理员, I want 浏览器关闭再打开后仍保持登录, so that 不必重复输入密码。
12. As an 管理员, I want 登录状态固定保留一年, so that 自己的设备可以长期方便地管理服务。
13. As an 管理员, I want 登录期限不会因日常访问不断延长, so that 到期后仍需重新确认身份。
14. As an 管理员, I want 服务重启或更新后保留有效登录, so that 维护服务不会中断浏览器身份。
15. As an 管理员, I want 电脑和手机分别登录, so that 能从多个自己的设备管理服务。
16. As an 管理员, I want 在当前浏览器主动退出, so that 不再允许该浏览器继续管理。
17. As an 管理员, I want 退出时服务端撤销会话, so that 复制过的旧凭据也不能继续访问。
18. As an 管理员, I want 当前浏览器退出不影响其他设备, so that 可以分别管理各设备的登录。
19. As an 管理员, I want 会话过期或失效时页面提示重新登录, so that 不会把未授权请求误认为保存成功。
20. As an 管理员, I want 忘记密码时通过 SSH 重置, so that 无需建设邮箱找回系统。
21. As an 管理员, I want 重置密码时立即撤销所有会话, so that 凭据疑似泄露后能够恢复控制。
22. As an 管理员, I want 原密码和被撤销的会话在重启后仍然失效, so that 更新服务不会恢复旧权限。
23. As an 管理员, I want 未登录者不能读取通知目标、QQ 号备注和仓库订阅, so that 管理信息不会因公网访问泄露。
24. As an 管理员, I want 未登录者不能读取配置和 Issue 追踪清单, so that 管理数据只有授权浏览器可见。
25. As an 管理员, I want 所有管理写操作验证身份, so that 攻击者不能通过直接调用 API 绕过登录页。
26. As an 管理员, I want 登录后仍有跨站请求防护, so that 访问其他网站不会触发后台管理操作。
27. As an 管理员, I want 密码和会话只通过 HTTPS 传输, so that 网络链路不能直接读取它们。
28. As an 管理员, I want 页面脚本不能读取登录 Cookie, so that 减少凭据泄露机会。
29. As an 管理员, I want 继续正常管理监控仓库、轮询间隔、通知目标和仓库订阅, so that 接入登录不改变现有业务行为。
30. As an 管理员, I want 继续正常管理共享 Issue 追踪和追踪命令权限, so that Web 登录不会改变 QQ 命令授权规则。
31. As an 运维者, I want 应用端口仍只通过宿主机回环访问, so that 公网请求不能绕过 HTTPS 代理。
32. As an 运维者, I want 内部健康检查继续工作, so that 现有部署验收仍可判断服务状态。
33. As an 运维者, I want 健康状态不通过公网匿名暴露, so that 内部运行信息仍处于管理权限边界内。
34. As an 运维者, I want IP 证书自动续期并加载, so that 短期证书不依赖频繁手动维护。
35. As an 运维者, I want 80 端口仅用于证书验证, so that 登录和管理数据不会通过明文 HTTP 提供。
36. As an 运维者, I want 续期失败有可检查的结果和恢复说明, so that 能在证书过期前发现问题并处理。
37. As an 运维者, I want 证书失效时不降级为明文管理, so that 故障不会改变传输安全边界。
38. As an 运维者, I want SSH 恢复通道继续可用, so that 浏览器无法访问时仍能修复密码、证书或代理。
39. As an 运维者, I want 部署步骤检查端口冲突、网络可达性和配置有效性, so that 不会在未验证条件下公开服务。
40. As an 运维者, I want 密码和会话凭据不进入日志、URL 或版本库, so that 诊断和发布过程不会暴露管理权限。

## Implementation Decisions

- 这是一个本地单管理员身份，使用密码登录；不新增账户注册、多人角色、第三方 OAuth 或邮箱找回。Web 管理员身份与 QQ 通知目标、仓库订阅及追踪命令权限相互独立，QQ 身份不能代替 Web 登录。
- 在现有管理 HTTP 入口增加统一身份认证边界，覆盖管理页面、管理读取与写入 API，以及公网健康状态访问。登录页面及其必要静态资源、登录提交是明确的匿名例外；不得因静态资源例外泄露管理数据。不能只在前端隐藏页面或按钮。
- 为本地管理员凭据和可撤销会话增加持久化状态，优先复用现有 SQLite 存储及迁移机制。只保存带盐的现代密码哈希；会话使用密码学安全的随机凭据，服务端保存用于验证的摘要及创建、到期、撤销信息，不把密码或可直接使用的会话值写入数据库日志、URL 或版本库。
- 提供通过 SSH 可调用的初始密码设置和密码重置管理入口。秘密输入避免命令行参数和 shell 历史；没有默认密码。未初始化、认证配置非法或认证状态不可读取时，管理访问拒绝开放，不允许退回匿名管理。
- 每次成功登录创建独立会话，固定有效期定义为登录成功后 365 天，不因访问续期；持久化后跨进程重启、容器更新保持有效。浏览器主动删除 Cookie、隐私模式清理或会话被撤销后需重新登录，不能承诺浏览器一定保存整整一年。
- Cookie 使用 Secure、HttpOnly、SameSite=Strict、根路径和与服务端到期一致的持久化期限，不设置跨域共享。浏览器不保存密码，不使用 localStorage 保存会话凭据，客户端提供的到期信息不能覆盖服务端判断。
- 登录成功时签发新的随机会话，不接受客户端选择的会话标识。多个设备的会话独立；退出同时撤销服务端当前会话并清除 Cookie，重放退出前凭据必须失败。密码重置与全部会话撤销应原子生效；重置成功后旧密码及所有旧会话立即无效，包含已打开页面后续发出的请求。
- 提供登录、退出及当前认证状态的 HTTP 操作。未认证的管理 API 返回 401，已经认证但不符合跨站写入保护的请求返回 403；登录限流返回 429 并提供重试提示。页面访问引导到登录，页面 API 收到 401 时提示重新登录，不能自动重放未确认结果的业务写操作。
- 登录尝试限制至少覆盖单来源以及全局总量，控制密码哈希校验的资源消耗，使用可恢复的退避或时间窗口，避免永久锁死唯一管理员。来源识别仅信任已配置的本机代理；不得让伪造转发头绕过限制。具体阈值由实现选择、记录，并用行为测试验证。
- 保留并适配现有跨站写入防护，将允许来源从回环 HTTP 改为显式配置的公网 HTTPS Origin；不通过放宽为任意 Host、Origin 或转发头解决兼容问题。登录与退出也需跨站防护。固定的管理请求头不是身份凭据，CORS 不授予任意来源带凭据的访问权限。
- 公网访问地址使用 IP、443 和根路径，不增加 `/xxx` 前缀。默认部署地址为 `https://172.197.176.142/`；IP、外部 Origin 和证书目标以部署配置保持一致，不硬编码进业务逻辑。
- 推荐采用宿主机 Nginx 终止 TLS，再转发到既有宿主机回环 8081；容器服务的对宿主机端口映射仍仅绑定回环。代理覆盖客户端提供的身份相关转发头，应用只信任明确的代理边界。管理身份认证在应用管理 API 边界执行，不能依赖仅保护代理首页。
- 公网 TCP 80 只响应 ACME HTTP-01 验证路径，其他路径拒绝，不提供登录、管理静态页面或 API。TCP 443 提供 HTTPS 管理入口。部署时验证宿主机及云网络规则，8081 不对公网发布。
- 使用 Certbot 5.4 或更高版本的 webroot 能力申请 Let's Encrypt shortlived IP 证书；先通过测试环境验证流程，再签发生产可信证书。配置无人值守续期，续期成功后先验证代理配置，再重载证书。不得反复手动申请替代自动续期，也不得假设任意端口可替代 HTTP-01 要求的公网 80。
- 保留宿主机回环健康检查作为明确的内部例外；公网对同一健康状态资源必须要求有效登录，或明确拒绝由公网代理访问。该例外不得扩大到管理数据或管理写操作；不能仅依据客户端可伪造的 Host 或转发头启用内部豁免。
- 更新安装、部署、使用和恢复说明，包含初始化、重置密码、撤销全部会话、首次证书签发、自动续期检查和故障处理。证书过期或认证失败不得降级为 HTTP 或匿名管理。
- 沿用现有数据库升级和部署失败处理边界：新版本启动验收失败后停止并报告，保留证据，由人工决定恢复旧数据库与镜像，不自动回滚数据库。手动恢复旧数据库可能恢复旧会话状态，恢复指引应要求重置管理员密码并撤销全部会话，再重新开放公网。

## Testing Decisions

- 只断言外部行为、请求响应及持久化后可观察的结果，不断言私有函数、表名、密码哈希内部格式或 DOM 层级。主要测试边界是现有真实管理 HTTP 服务：临时数据库、临时监听端口、HTTP 客户端及实际请求；不为测试新增生产管理端点。
- 现有先例包括后台管理 HTTP 集成测试、健康面板 HTTP 测试、配置热加载及数据库重启测试，以及管理页面脚本的 DOM/网络测试。优先扩展现有 fixture；时间边界复用项目可控时钟模式，必要时只在统一认证组件增加时钟依赖，不等待真实一年。
- 使用者已确认测试边界：沿用现有 HTTP 集成测试，从真实请求验证登录、Cookie、会话与管理 API；另用部署验收覆盖 HTTPS、端口隔离和自动续期。
- 身份保护矩阵覆盖全部管理读取、写入和公网健康状态入口：无凭据、伪造凭据、过期凭据和已撤销凭据均无法访问；正常登录后可完成已有管理操作。固定管理请求头、伪造 Origin/Host 或转发头不能替代会话。
- 登录覆盖未初始化拒绝管理、正确和错误密码、限流触发及恢复、恶意伪造来源头，以及每次登录产生独立可用会话。验证错误提示和日志不包含密码或会话值。
- Cookie 覆盖 Secure、HttpOnly、SameSite、持久化期限及作用域。HTTP 测试校验响应契约，浏览器 HTTPS 验收验证 Cookie 实际保存、携带以及脚本不可读取，避免在纯 HTTP fixture 中误判 Secure Cookie 行为。
- 生命周期覆盖一年边界前后、访问不续期、服务重启、两个设备分别登录、退出仅撤销当前会话、重放旧 Cookie 失败、密码重置撤销全部会话，以及重置后重启仍保持撤销结果。
- 通过同一 HTTP 边界验证服务运行时执行本地密码重置的效果，已打开页面随后请求必须失效；并发登录不能在重置完成后留下以旧密码获得的有效会话。
- CSRF 覆盖跨站登录、退出与各类管理写请求被拒绝，允许的公网 HTTPS Origin 正常工作；恶意 Origin、错误端口或协议、伪造代理头不能扩大授权范围。正常页面操作继续通过现有请求机制完成。
- 前端覆盖登录成功、密码错误、限流提示、退出、Cookie 清除后重新登录，以及管理请求收到 401 时显示真实结果；认证失效不能显示保存成功，也不能盲目重试写请求。
- 部署验收作为独立于业务逻辑的必要边界：从外部验证可信 TLS、443 可达、80 仅允许挑战路径、8081 不可公网访问、管理数据不可匿名读取；从宿主机验证既有回环健康检查继续工作。伪造 Host 和转发头不得让公网请求获得内部健康检查豁免。
- 自动续期先用 ACME 测试环境或 dry-run 验证调度、挑战路径和重载流程；覆盖续期失败可观察、错误证书或配置不能替换正常配置、失败时不开放 HTTP 管理。生产签发与外部验收属于实施部署阶段，不能在普通测试中反复请求生产证书。
- 保留现有通知目标、仓库订阅、监控仓库管理、Issue 追踪、追踪命令权限及通知投递回归测试；既有管理测试显式建立认证会话，不通过全局关闭认证维持通过。

## Out of Scope

- 域名配置、额外路径前缀或明文 HTTP 管理入口。
- 多管理员、注册、角色权限系统、第三方登录、邮箱找回、双因素认证或通行密钥。
- 面向 QQ 通知目标的 Web 用户账户、按仓库授予 Web 管理权限，或改变追踪命令权限语义。
- 浏览器内的设备会话列表、逐设备远程撤销界面；本期通过当前会话退出和 SSH 全量撤销满足恢复需求。
- 滑动续期、永不过期登录、浏览器密码存储和保证 Cookie 一定保留一整年。
- 改变业务监控、仓库订阅、Issue 追踪和通知投递语义。
- 全面安全审计、外部通知渠道、复杂认证审计平台或数据库恢复策略重构。
- 在本次规格生成中实现功能、连接线上、安装代理、申请生产证书或开放防火墙。

## Further Notes

- 本规格综合本次访谈 Q1–Q9：单管理员、IP 地址、HTTPS、根路径、本地密码、一年登录、重启保留、多设备独立会话、SSH 恢复，以及 443 管理加 80 验证。用户最初提出 HTTP，后已明确接受 HTTPS；不得按最初表述部署明文登录。
- 架构草案 ADR 0006 记录该方案；数据库迁移和恢复继续遵守 ADR 0002。此前仓库订阅规格将登录列为其范围外，本规格作为独立功能增加认证，不改变其领域规则。没有新增项目专属领域概念，不把 Cookie、会话等通用技术术语写入领域词汇表。
- 一年会话意味着泄露后的风险窗口较长；使用者已明确选择此期限。HTTPS 和安全 Cookie 降低泄露风险，不能消除终端被入侵或凭据被复制后的风险，全量撤销是必要恢复手段。
- Let's Encrypt IP 证书截至调查时已正式可用，准确有效期为 160 小时，因此自动续期是必要依赖，而不是可选优化。依据：[正式可用公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)、[Certbot IP 证书指引](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)、[验证方式与端口要求](https://letsencrypt.org/docs/challenge-types/)。
