# 01: 后台配置仓库订阅，统一按订阅分发

Status: ready-for-agent
Implementation: complete
Blocked by: None (can start immediately)

**What to build:** 管理员在现有后台为每个 QQ 私聊通知目标查看、选择并一次保存完整仓库清单，新建 Issue 与共享 Issue 追踪动态统一按仓库订阅发送。已有用户升级保留原接收范围，新增用户从空订阅开始，个人订阅不改变共享抓取和追踪。依据父规格与 ADR 0005，沿用独立投递及全局监控周期约束。

**Blocked by:** None (can start immediately).

- [x] 沿用现有通知目标身份和 QQ 号备注，以 OpenID 投递；仓库订阅是独立的多对多关系，同一关系唯一，仓库身份沿用现有格式校验和大小写不敏感规则。
- [x] 后台列表显示完整仓库清单，并有可用的多选与保存入口。支持一次替换完整清单和空清单，刷新或重启后配置保留；空订阅不表示接收全部。
- [x] 管理接口验证目标存在、仓库属于当前生效的全局仓库池，沿用现有管理写入校验；非法输入或过期目标不产生部分修改。重复仓库按规范化身份处理。
- [x] 新建 Issue 和所有追踪动态在发现入库时确定订阅接收者，保持全局事件去重与每个接收目标独立投递、重试；不在发送时为后来加入者追加历史接收关系。
- [x] 订阅前已发现的 Issue 和动态不补发；创建早于个人订阅、发现晚于订阅的 Issue 可通知，但仍受全局监控周期基线约束。
- [x] 保存清单时原子取消被移除关系的新建 Issue 和追踪动态待发送、待重试及可人工重试失败投递，保留已发送历史。重新订阅不恢复已取消投递，其他目标、其他仓库及共享追踪不受影响。复杂在途竞争的补强和专项验证由 02 承担。
- [x] 一次性迁移仅为升级前已有通知目标建立当前全部生效监控仓库的显式订阅，保留目标身份、备注、去重历史、已完成投递和仍有效积压，不为历史发现新增投递。
- [x] 迁移兼容旧单人绑定链路，先落实最终有效全局仓库范围，避免授予已移除仓库；没有旧目标的安装为空订阅。迁移完成标记持久化，重复启动或打开连接不恢复取消关系，也不自动分配后续新增目标或仓库。
- [x] `/bind` 与后台新增目标均从空订阅开始；重复绑定保留原配置。解绑及后台删除清除仓库订阅、备注并取消全部未完成投递，重新绑定使用新身份且为空订阅。
- [x] 无人订阅时仍继续抓取、记录新 Issue 和维护共享追踪；此后有人订阅不补发这段已发现历史。
- [x] 追踪命令仍分别授权，与仓库订阅无关；有权限但未订阅仓库仍可管理共享追踪，无权限者不因订阅获得权限。
- [x] 通过真实后台 HTTP API、持久化、发现/追踪入口及模拟 QQ 发送，验证甲订阅 A、乙订阅 B、丙订阅两者、丁为空的接收矩阵；覆盖评论、引用、关联 PR 状态与关闭动态。
- [x] 覆盖保存失败原子性、时间边界、独立重试、升级与重启幂等、绑定解绑；提供基本管理脚本 DOM/网络行为验证。更新受影响的旧测试为显式订阅，同时保留原有可靠性断言，不新增生产测试接口。

## Scope Notes

本工单交付可实际配置并影响两类通知的最小完整路径。搜索、全选、清空、数量展示、完整反馈和说明由 04 完善；全局移除清理由 03 完善。不得为了分期把任一类新发现消息继续发给未订阅者，不引入个人追踪或用户仓库订阅 bot 命令。
