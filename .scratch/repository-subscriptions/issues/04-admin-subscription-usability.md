# 04: 完善后台订阅操作与状态说明

Status: ready-for-agent
Implementation: complete
Blocked by: 01

**What to build:** 管理员在现有通知目标管理入口快速识别用户、检查接收范围并完成仓库搜索、多选、全选和清空，获得准确保存反馈；绑定提示、健康统计及使用说明清楚表达空订阅与按仓库接收的新规则。

**Blocked by:** 01 — 后台配置仓库订阅，统一按订阅分发。

- [x] 通知目标列表显示 QQ 号备注、订阅数量及仓库；保留现有用户搜索、分页、备注编辑和页面导航，不将备注作为绑定或投递身份。
- [x] 从全局生效仓库池多选，支持搜索、全选和清空；全选指当前全局仓库池，搜索只改变可见项，隐藏选择不被丢弃。
- [x] 一次保存完整清单；显示明确的“未订阅任何仓库”状态，清空不删除通知目标，也不被解释为订阅全部。
- [x] 保存进行中防止重复提交或输入被意外丢弃；失败时提供明确错误并保留可修改的选择，不显示虚假成功。非法或已移除仓库及过期目标按接口错误反馈处理。
- [x] 仓库名称、OpenID、QQ 号备注等用户输入以文本安全呈现，沿用管理写入校验。
- [x] `/bind` 回复准确表达新目标没有仓库订阅、需要管理员配置；重复绑定保留配置，解绑提示符合删除目标及清理订阅的语义，不新增仓库订阅命令。
- [x] 健康统计能区分通知目标存在与存在仓库订阅，不因空订阅误导为接收全部；已取消投递不计入待发送积压，保持原有健康展示兼容。
- [x] 使用说明覆盖升级保留现有范围、新增目标和仓库不自动订阅、发现时确定接收者、不补发、取消后在途可能到达、共享追踪权限独立等已确认规则。
- [x] 复用执行真实管理脚本的 DOM/网络边界测试，验证搜索后保存完整清单、全选、清空、空状态、保存进行中和失败恢复；避免断言固定 DOM 层级。
- [x] 结合真实后台 API 和持久化结果验证列表、数量及健康统计与实际订阅和投递一致；保留现有用户搜索、分页、备注和导航相关回归测试。

## Scope Notes

完善 01 的可用基本界面，不增加按仓库批量分配用户的第二套入口、用户登录系统或个人筛选规则。与 02、03 无直接阻塞关系；它们扩展的行为继续遵循同一规格，相关错误和取消状态使用既有反馈方式呈现。
