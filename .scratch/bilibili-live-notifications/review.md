# Bilibili 开播通知实现审查

基线：1610cc45dd9fccf0f4f4d1b16ab480cc63d7b491（本轮实施开始时的 HEAD）。按五张纵向工单实施；规范和规格由独立只读子代理分别审查，复审基于 65cda2c，本文与完成记录随最终提交保存。

## Standards

初审提出三项实质问题：同步数据库锁等待可能阻塞异步执行线程；认领后数据库错误可能使投递停留在 sending 直至重启；节流预约与真实请求开始之间存在时间间隙。

已将直播数据库初始化和操作放入 spawn_blocking，并复用串行缓存连接；采用即时写事务。投递增加 120 秒认领租约与递增认领身份，支持进程内回收且旧任务不能覆盖新认领结果。共享发送许可覆盖最终复核和 HTTP 请求，按请求完成时间控制下一次发送，Issue、追踪动态和直播通知共用约束。

补充数据库锁竞争不中断异步执行、无重启回收认领、慢验证时实际 HTTP 发送间隔测试。复审确认三项均已解决，无新增实质问题。将裸整数/字符串状态进一步枚举化仅为低优先级维护性建议，不扩大本轮重构。

## Spec

初审提出一项缺陷：已知直播订阅的命令退订仍依赖 Bilibili 查询，在外部故障时无法取消。

已优先使用保存的真实房间号及经过验证的短号映射执行本地退订，未知映射才请求外部接口。真实本地 HTTP 模拟故障后分别验证真实号和缓存短号均能取消。复审确认原问题已解决，无新增可操作规格问题或范围扩张。
