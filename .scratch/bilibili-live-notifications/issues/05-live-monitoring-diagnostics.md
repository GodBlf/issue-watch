# 05: 后台监控状态与失败诊断

**What to build:** 管理员通过控制台判断直播间是否正在被检查、谁在订阅以及提醒为何未送达，无需从数据库或日志手工拼接运行状态。

**Blocked by:** 04 — 投递重试、过期取消与重启恢复。

Status: ready-for-agent
Implementation: complete

- [x] 提供共享直播间列表，展示可识别的主播名称、真实房间号、直播状态、有效订阅人数、最近检查时间和检查异常。
- [x] 以共享房间为单位展示检查结果，而不是为每个通知目标伪造重复监控记录；订阅数量与后台和 QQ 共用的有效关系一致。
- [x] 查询失败时可区分最近检查失败与上次成功的直播状态，不能把过期的成功状态伪装成实时成功，也不能把未知状态显示成确认下播。
- [x] 新增、移除订阅和最后一人退订后的页面状态与实际监控范围一致；无直播订阅或无诊断记录时展示明确空状态。
- [x] 展示开播通知的永久投递失败，能识别对应通知目标、房间和失败原因；不新增手动重发或旧场次补发能力。
- [x] 诊断读取与页面入口沿用现有管理鉴权，未经登录不能取得管理数据；主播名称、标题和失败内容按普通文本呈现。
- [x] 管理 API 与页面交互测试覆盖正常直播、离线、未知、接口异常、永久发送失败、空状态及状态刷新，以真实持久化状态或受控接口响应为依据。
- [x] 对完整功能执行从后台或命令订阅、发现开播、QQ 投递、退订和查看诊断的集成回归；原有仓库配置、Issue 追踪、管理登录与后台导航保持可用。

## Scope Notes

本工单消费已由前置工单保存的真实检查和投递状态，不另建第二套监控逻辑。正式环境部署、真实外部接口可用性验证和 QQ 平台权限配置不属于本工单。
