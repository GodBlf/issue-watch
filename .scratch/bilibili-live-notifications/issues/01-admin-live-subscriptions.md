# 01: 后台管理直播订阅

**What to build:** 管理员在现有通知目标编辑界面添加、查看和移除直播订阅，输入房间号或链接即可验证并保存正确的直播间。建立后续共享监控和 QQ 自助命令共用的直播订阅能力，保持现有仓库订阅独立。

**Blocked by:** None (can start immediately).

Status: ready-for-agent
Implementation: complete

- [x] 通知目标可订阅多个直播间，同一直播间可由多个通知目标订阅；后台展示主播名称和真实房间号，明确显示空订阅状态。
- [x] 接受数字长房间号、短房间号和 `https://live.bilibili.com/房间号` 链接，通过统一的房间解析能力归一化为真实房间号；主播 UID 不作为房间输入。
- [x] 同一通知目标对同一真实房间只能有一份有效订阅；重复添加或换用短号、链接不产生重复关系。
- [x] 添加前验证房间并取得可用于反馈的直播快照。不存在或验证接口失败时明确反馈，不留下新订阅，不影响现有配置。
- [x] 已在直播时添加订阅，只在后台操作结果反馈当前状态和链接；保存当前场次基线，使后续监控不会向新订阅补发该场次。
- [x] 移除单个直播订阅不影响其他目标或仓库订阅；后台删除整个通知目标时同时清除其直播订阅。持久化订阅，数据库重开后配置仍可读取。
- [x] 维护可供共享监控使用的有效订阅范围，首个订阅激活房间、最后一个移除后停用；重新订阅不恢复已删除的关系。
- [x] 房间解析与快照获取具有统一外部边界，可使用本地模拟服务；不为后续直播通知伪造 GitHub Issue 数据。
- [x] 新增管理能力沿用现有管理员登录与写请求保护；外部标题和主播名称作为普通文本呈现，提交期间的错误和成功状态可见。
- [x] 通过真实临时数据库、已登录管理 API 和页面 DOM/网络行为测试验证添加、查询、移除、去重与失败场景；自动测试不访问真实 Bilibili。
- [x] 数据库升级保留现有通知目标、备注、仓库订阅、Issue 追踪与投递记录；现有功能回归通过。

## Scope Notes

本工单以后台配置可用为验收终点，不要求已发送开播通知。共享检查和发送由 02 接通，QQ 自助入口由 03 接通。领域遵循 ADR 0007 的直播订阅生命周期及 ADR 0005 的独立仓库生命周期。
