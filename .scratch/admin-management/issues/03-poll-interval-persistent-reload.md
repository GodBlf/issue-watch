# 03: 轮询间隔在线修改与持久化热加载

Status: ready-for-agent
Implementation: complete
Blocked by: None (can start immediately)

**What to build:** 管理员在现有健康网页查看和修改轮询间隔，将设置可靠保存到服务使用的配置文件，经现有热加载机制生效，重启后保留；同时支持安全的外部文件编辑和 Docker 部署。

- [x] 页面展示当前轮询间隔，表单和接口只接受 1–86400 秒的整数，对越界及非法输入给出明确错误。
- [x] 配置写回同一份运行配置，保留监控仓库、数据库路径等其他配置值；继续支持手动编辑，数据库路径等非热加载配置不能通过此操作更改。
- [x] 保存采用可靠的文件替换方式，写入失败不破坏已有配置；重启后使用已保存的间隔。
- [x] 页面提交携带所读配置的版本依据；读取后文件已变化或其他管理提交已保存时，拒绝过期覆盖并提示刷新。外部文件无效时不得用旧页面内容静默覆盖。
- [x] 明确区分未保存、已保存待加载、配置已接受待应用和监控任务已采用新配置；加载或保存失败可见，不将 HTTP 保存成功当作热加载完成。
- [x] 正在进行的轮询/投递不被取消，新配置在当前任务完成后用于下一轮检查；间隔更改不重置仓库进度或广播订阅。
- [x] 写接口校验请求来源并拒绝跨站修改；正常本机及 SSH 隧道访问可以保存，宿主机端口继续仅绑定回环地址。
- [x] 本地及生产 Docker 配置改为可写目录挂载，支持可靠替换保存；更新首次部署、已有配置迁移和运行说明，保留数据卷及凭据处理方式。
- [x] 原有部署更新与恢复流程在新挂载下仍能找到并保留配置，不实施数据库自动回滚；验证部署和容器读写权限。
- [x] 管理操作和断连时保留已有健康信息，恢复连接后刷新状态，不增加公网登录或重启操作。
- [x] 验证合法/非法间隔、保存失败、文件及并发提交冲突、热加载各阶段、持久化重启、浏览器流程、跨站拒绝及 Docker 配置读写。
