# 01: 广播订阅查看与添加

Status: ready-for-agent
Implementation: complete
Blocked by: None (can start immediately)

**What to build:** 管理员通过现有健康网页查看广播接收者，并使用当前机器人的 user_openid 和选填 QQ 号备注添加广播订阅。继续通过本机地址或 SSH 隧道访问，复用健康展示，不增加公网账户体系。

- [x] 页面展示当前广播订阅的 user_openid 和 QQ 号备注，支持空列表，并刷新反映机器人 /bind、/unbind 引起的变化。
- [x] 添加表单明确要求 user_openid，拒绝空身份，不提供普通 QQ 号查找或发送目标转换；提示保存订阅并不意味着已验证官方平台发送权限。
- [x] QQ 号备注选填且不要求唯一，仅供人工识别，不用于发送或验证身份。
- [x] 页面和管理接口可以添加订阅；同一 user_openid 重复添加不创建重复订阅，不隐式覆盖现有备注或重置投递状态。
- [x] 新订阅不补发已发现的历史通知或其他接收者积压，后续新发现的 Issue 按现有广播逻辑投递。
- [x] 订阅和备注重启后保留；已有订阅及其投递记录在存储升级后继续有效，符合既有广播投递与部署恢复决策。
- [x] 写接口校验请求来源，拒绝非预期来源的跨站修改请求；正常本机及 SSH 隧道访问可完成操作，不开放跨来源写访问。
- [x] 列表加载和提交有明确的进行中、成功与失败反馈；用户输入作为文本展示，失败不清空原有健康数据，原页面刷新及断连恢复行为保持正常。
- [x] 完成管理接口、真实持久化、重复添加、新订阅投递边界、跨站拒绝和浏览器添加流程的必要验证，复用既有测试方式。
