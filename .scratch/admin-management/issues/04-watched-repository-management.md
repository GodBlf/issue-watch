# 04: 监控仓库在线添加与移除

Status: ready-for-agent
Implementation: complete
Blocked by: 03 — 轮询间隔在线修改与持久化热加载

**What to build:** 管理员在现有健康网页查看、添加和移除所有广播订阅共享的监控仓库，复用配置保存、冲突检测及热加载状态反馈，保持现有监控进度和通知投递语义。

- [x] 页面展示共享监控仓库列表，明确所有广播接收者使用同一份配置，支持添加和确认后移除。
- [x] 页面和接口沿用 owner/name 格式及大小写不敏感的重复校验，拒绝非法或重复仓库；至少保留一个仓库，删除最后一个时说明原因。
- [x] 添加首次监控的仓库只建立当前时间基线，不发送历史 Issue；后续新建 Issue 正常发现并投递。
- [x] 移除停止后续轮询，保留已发现的待发送或待重试通知继续投递；已有请求不因配置修改被取消。
- [x] 移除时说明队列继续投递及重新添加会恢复进度；重新添加曾监控的仓库时明确提示补发停用期间的新建 Issue。
- [x] 重新添加恢复原监控进度且不重置去重记录；首次添加、移除及重新添加不改变广播订阅或 QQ 号备注。
- [x] 配置修改持久保存且重启保留，不覆盖轮询间隔或非热加载配置；外部编辑和过期页面提交沿用冲突保护。
- [x] 沿用保存、加载接受及任务实际采用配置的阶段反馈，保存或加载失败明确可见并保留上一份有效配置。
- [x] 新增写操作复用请求来源防护，列表刷新能反映外部配置修改；健康展示、逐仓库检查状态及断连恢复继续正常。
- [x] 完成管理接口与浏览器增删验证，并覆盖最后一个仓库保护、重复校验、基线、停用期间补发、队列继续投递、冲突及重启持久化。
- [x] 更新管理说明，明确共享配置、仓库移除与订阅移除的不同语义，以及零监控仓库能力不在本 ticket 范围内。
