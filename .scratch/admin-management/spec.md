# 现有健康网页扩展管理员管理功能

本规格记录 grill-with-docs 会话已确认的决策；用户已确认 tickets 拆分并授权 implement。实现与验证记录见各独立 ticket。

## 目标与入口

在现有健康网页基础上增加广播订阅、监控仓库和轮询间隔管理，复用现有健康展示。面向部署管理员，继续通过本机地址或 SSH 隧道访问，保持宿主机回环地址限制，不增加公网登录入口。写接口应校验请求来源并防止跨站请求触发修改；隧道访问本身不能替代写接口的请求防护。

## 广播订阅管理

- 展示当前订阅及其 user_openid、QQ 号备注，支持手动添加和移除。
- 保留机器人 /bind 和 /unbind；手动添加填写当前机器人的 user_openid，普通 QQ 号不能作为发送目标。
- 同一 user_openid 重复添加不创建重复订阅；订阅添加成功不等于已验证官方平台发送权限。
- QQ 号备注选填，可补填、修改和清空，不要求唯一，不验证 QQ 身份，不用于发送；通过 /bind 加入的订阅也可维护备注。
- 备注持久化，服务重启后保留；移除订阅时删除备注，重新加入后不恢复备注。
- 新订阅不补发历史通知；移除取消未发送投递，已发出的请求可能仍送达；重新加入创建新的订阅身份，不恢复旧积压，遵循 ADR 0001。
- 移除不封禁接收者，对方可通过 /bind 重新加入。

## 监控仓库与轮询间隔

- 展示、添加和移除共享监控仓库；所有广播订阅共享这份列表。
- 沿用 owner/name 格式及大小写不敏感的重复校验，至少保留一个仓库；页面和接口都拒绝移除最后一个仓库。
- 首次添加仓库建立当前时间基线，不发送历史 Issue；移除停止后续轮询，已有待发送通知继续投递；重新添加恢复原进度，补发停用期间的新建 Issue。
- 移除及重新添加时说明对应投递语义，并对移除操作提供确认。
- 支持修改轮询间隔，合法整数范围为 1–86400 秒。
- 写回当前 config.toml，重启后保留，继续支持手动编辑文件；保留数据库路径等非热加载配置。
- 沿用现有热加载机制，正在执行的轮询/投递不会被取消，新设置在当前任务完成后用于下一轮检查。
- 区分保存成功、配置被接受和监控任务实际采用新配置的状态；加载或保存失败明确提示，不将保存成功误报为已生效。
- 提交时检测页面读取后配置文件的变化，存在冲突时拒绝覆盖并提示刷新。
- 配置保存采用可靠的文件替换方式，本地和生产 Compose 改为可写配置目录挂载，并同步相关运行与部署说明。

## 验收

- 原健康网页及断连恢复行为正常，管理操作失败不会清空已有健康信息。
- 接收者添加、重复添加、备注修改/清空、移除及重新加入符合以上语义；备注与订阅状态在重启后保持一致。
- 页面列表能够刷新反映 /bind、/unbind 引起的变更。
- 仓库添加、移除、重新添加和间隔修改可持久化并热加载，非法配置和空仓库列表被拒绝。
- 配置外部变更与页面过期提交不会被静默覆盖；保存失败保留原有效配置，正确提示未保存或未生效。
- 写接口拒绝非预期来源的跨站修改请求；本地与生产 Compose 继续仅发布宿主机回环端口。
- 验证广播投递、配置热加载及健康展示的既有行为，增加必要的管理 API、持久化、冲突和浏览器交互验证。

## 范围边界

第一版不包含公网账户体系、订阅封禁、QQ 群通知、普通 QQ 号查找 OpenID、独立订阅仓库/筛选规则、暂停订阅、通知手动重试、主动测试消息、服务重启、凭据/数据库路径/监听地址在线修改。

零监控仓库能力由 `.scratch/empty-repository-monitoring/issues/01-allow-empty-repositories.md` 单独记录，本规格保留至少一个仓库的现有约束。
