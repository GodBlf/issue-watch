# Issue 追踪

## 已确认的决定

- 指定 Issue 的追踪清单全局共享；动态发送给所有广播订阅者。QQ 命令和 admin 后台管理同一份清单，取消追踪影响所有接收者。
- 首版包含新评论、其他 Issue/PR 引用、PR 明确关联以及 Issue 关闭；不通知无关 PR，暂不包含标题、正文、标签和指派人修改。
- 定时检查新动态，无变化不发送；一次检查发现的多条动态合并通知。
- 追踪检查间隔使用独立配置字段，默认 5 分钟，admin 后台可修改，沿用现有轮询间隔配置的管理方式。
- 不设 QQ 管理员角色；所有 QQ 用户默认没有追踪修改权限。admin 后台按 `user_openid` 分别授予添加追踪和取消追踪权限。
- 添加和取消权限独立；取消权限允许取消任意共享追踪。权限与广播订阅独立，退出订阅不删除权限，未订阅的授权用户也可管理追踪。
- 未授权回复：`权限不足：你没有执行此命令的权限，请联系后台管理人员。`
- admin 后台可管理指定仓库的追踪 Issue，手动添加和取消。
- Issue 关闭时发送最后一条通知，自动清理并停止追踪。
- 仅允许追踪已配置的监控仓库。移除仓库时同时取消它的全部追踪，后台提交前显示影响数量。
- 添加时回复当前标题、状态和链接，从添加时开始通知新动态，不补发历史；关闭的 Issue 拒绝添加，重复添加提示已在追踪中。
- 所有关闭原因均结束追踪，包括已解决和未计划处理；从当前追踪列表移除，保留必要投递记录供关闭通知重试。重新打开不自动恢复，需重新添加。
- PR 引用和 GitHub 明确关联均通知；明确关联的 PR 后续合并、关闭和重新打开也通知，仅引用的 PR 不跟进状态。相同 PR 的引用与关联尽量合并。
- 命令仅接受完整 Issue URL：`/track <Issue URL>` 添加，`/untrack <Issue URL>` 取消；添加时对应 Issue 不存在，回复“该 Issue 不存在”。
- `/tracking` 查询共享清单；`/tracking <仓库 URL>` 按仓库查询。广播订阅者或具有任一追踪修改权限的用户可查询，其他用户返回权限不足。
- 间隔范围 1–86400 秒，保存后热加载，从保存时重新计时；正在执行的检查完成，不启动重叠检查。
- 手动取消时取消该次追踪未发送投递，已发出请求仍可能送达；再次添加使用新的起点，不恢复旧积压。自动关闭保留最后一批动态与关闭通知供重试。
- 服务恢复后补查自上次成功检查以来的动态，合并并去重；单项失败不影响其他追踪，查询失败不视为关闭。已追踪 Issue 不存在或不可访问时后台显示异常，保留追踪等待恢复或手动取消。
- 每个 Issue 一条摘要：仓库、编号、标题、动态类型、操作者、评论节选或关联条目标题、链接。过长评论截断，单轮动态过多时展示数量及有限摘要。
- 不设置追踪数量上限。
- 后台在仓库管理中提供追踪列表，显示标题、链接、最近成功检查时间和异常信息，支持 URL 添加及单条取消；独立用户权限列表支持按 `user_openid` 管理两项权限，包括尚未订阅的用户。
- 撤销权限仅限制后续操作，不取消已有共享追踪；每次命令检查当前权限。重复取消回复“该 Issue 未在追踪中”。
- 追踪动态不经过新建 Issue 筛选规则。发现动态时确定接收者，新订阅不补发历史，退出订阅取消该订阅待发送投递。无订阅者时仍检查，但不向后来订阅者补发。
- 发现追踪开始后的关闭事件即结束追踪，即使检查时已经重新打开；最终通知说明关闭与当前状态，需重新添加才能再次追踪。
- 引用包含跨仓库来源，以 GitHub 提供且当前凭据可读取的记录为范围，不保证不可访问的私有引用或 GitHub 未识别的普通文本提及。
- 新功能同时优化 admin 前端，拆分当前集中在一个页面的管理内容，改善导航和编辑交互。
- 后台拆成五个独立视图，导航切换仅显示当前视图，并支持刷新后保持位置：概览（服务健康、投递队列、异常摘要）、仓库（仓库列表及仓库内的追踪管理）、广播接收者（订阅、添加、备注和移除）、用户权限（两项授权）、设置（独立的新 Issue 轮询与追踪检查间隔，以及保存/生效状态）。桌面侧栏，手机紧凑导航。
- 管理列表提供搜索与分页；添加和编辑使用独立表单或侧边面板，显式保存才提交。自动刷新保留未保存输入，离开未保存表单时提醒；字段及操作附近显示错误，提交期间防止重复操作。
- 取消追踪、移除订阅和移除仓库需要确认，移除仓库显示将取消的追踪数量；权限变更保存后反馈，不额外确认。

## 与现有规则的关系

- 延续 ADR 0001：动态发现时确定接收者，按订阅分别保存投递，新增订阅不补发，退出取消该订阅未发送投递。
- 移除仓库时，现有新建 Issue 通知仍按原规则继续投递；该仓库的追踪结束，并取消相应未发送的追踪动态。
- 不改变广播订阅本身的 `/bind`、`/unbind` 语义。追踪与广播订阅、命令权限各自独立。
