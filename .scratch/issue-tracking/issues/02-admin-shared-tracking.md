# 02: 后台添加、查询和取消共享 Issue 追踪

**Status:** ready-for-agent
Implementation: complete



**What to build:** 后台操作者在仓库详情中通过完整 Issue URL 管理持久化的共享追踪清单，建立新动态的追踪起点。

**Blocked by:** 01：后台拆分导航并保留现有管理流程

- [x] 仅允许添加已配置监控仓库中的真实 Issue；拒绝 PR 链接、无效 URL、已关闭 Issue和未配置仓库，给出明确原因。Issue 不存在回复“该 Issue 不存在”。
- [x] 添加结果显示标题、状态和链接；重复添加提示已在追踪中，不改变原追踪起点。不设置追踪数量上限。
- [x] 仓库详情提供追踪列表、搜索和分页；显示标题、链接、最近成功检查时间及异常状态，无检查结果时明确显示尚未检查。
- [x] 添加以当前时点建立基线，不补发历史；重启保留清单及基线，无订阅者也允许添加和保留追踪。
- [x] 单条取消经过确认后移除当前追踪；重复取消提示“该 Issue 未在追踪中”；再次添加建立新起点，不复用旧积压。
- [x] 共享追踪身份支持区分先前取消的追踪和重新添加的追踪，避免旧处理结果改变新的追踪。
- [x] 验证 URL 与 Issue 校验、重复及并发操作、取消后重新添加、重启持久化和后台读写流程。
