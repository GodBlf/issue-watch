# 05: 广播跨仓库引用及明确关联 PR

**Status:** ready-for-agent



**What to build:** 被追踪 Issue 被其他 Issue/PR 引用或被 PR 明确关联时，接收者收到可读的动态摘要。

**Blocked by:** 03：按独立间隔广播新评论并可靠投递

- [ ] 发现追踪开始后的 Issue/PR 引用及 GitHub 明确关联记录，包括可访问的跨仓库来源。
- [ ] 只保证 GitHub 提供且当前凭据可读取的引用，不通过普通文本猜测关联，不保证不可访问的私有引用。
- [ ] 同一 PR 的引用与关联尽量合并，保留可理解的关系说明；不把仅引用的 PR 当作需要跟进状态的明确关联 PR。
- [ ] 摘要包含操作者、来源仓库及编号、来源标题和链接，并复用同轮合并、长度控制及按订阅投递行为。
- [ ] 首次追踪不补发历史关联；建立必要基线，使后续明确关联 PR 状态跟进可衔接。
- [ ] 正确处理引用分页、失败补查、稳定去重；单项失败不推进对应成功进度，不影响其他追踪。
- [ ] 验证跨仓库引用、权限不足、引用与关联重叠、历史基线及重启补查。
