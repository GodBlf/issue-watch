# 配置热加载设计

目标：运行中增删监控仓库和修改轮询间隔，不重启服务、不改变 QQ 绑定或已有仓库进度。

后台任务每 2 秒重新读取 TOML，以内容比较检测变化，支持原子替换保存。先完整校验，再为新仓库持久化基线，最后通过 watch 通道发布有效配置。GitHub 监控循环在当前工作完成后接收最新配置，更新轮询定时器并开始下一轮；不取消正在执行的请求或投递。

无效配置继续沿用最后有效值，同一错误只记录一次，配置修复后自动恢复。仅仓库列表和轮询间隔可热加载。数据库路径改变会拒绝整个候选配置，凭据仍在启动时读取。删除仓库不删除持久化状态或队列，重新添加会恢复原进度。

验证在配置文件到监控配置发布的公共边界进行，使用临时文件和真实 SQLite，覆盖原子保存、新增基线、旧进度与绑定保留、无效/缺失配置回退及修复、删除再添加，以及后台配置更新。
