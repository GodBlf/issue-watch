# 通知目标按仓库订阅，共享抓取与 Issue 追踪

本次重构将 ADR 0001 的全体接收者共享仓库范围、ADR 0003 的向全体接收者发送追踪动态，改为按通知目标的仓库订阅分发；新建 Issue 与追踪动态使用同一订阅范围。保留全局监控仓库池、共享抓取与共享 Issue 追踪清单，允许每个通知目标选择多个仓库，以满足不同接收范围，同时避免本期引入个人独立追踪模型。

升级时为现有接收者建立当前全部监控仓库的显式订阅，以保留升级前的接收范围；升级后新增仓库不自动授予已有接收者。首期由管理员在后台管理仓库订阅，用户通过 bot 命令管理仓库订阅留待后续；不在本期增加筛选规则配置。

沿用现有 QQ 私聊通知目标，以 `user_openid` 标识，不引入独立登录账户，不以 QQ 号备注绑定。通知目标允许没有仓库订阅，此时不发送通知；全局仓库池中的仓库即使无人订阅，也继续抓取、记录新 Issue 并维护共享 Issue 追踪，个人订阅不控制全局监控生命周期。

新建 Issue 和追踪动态均按发现入库时的仓库订阅关系确定接收者，不补发订阅前已经发现的消息。因此 Issue 在订阅前创建、订阅后才被系统发现，仍可通知该订阅者。取消某个仓库订阅会取消该通知目标在该仓库的待发送、待重试投递，重新订阅不恢复这些投递；其他通知目标、全局监控和共享 Issue 追踪不受影响，已提交给 QQ 的请求可能仍然到达。沿用 ADR 0001 的独立投递机制与 ADR 0004 的全局监控周期规则。

现有 `/bind` 创建没有仓库订阅的通知目标，重复绑定保留已有配置；后台手动新增通知目标也从空订阅开始。`/unbind` 删除通知目标、QQ 号备注及全部仓库订阅，取消该目标全部未完成投递，重新绑定不恢复原配置或投递。此行为与升级时为已有接收者订阅当前全部仓库的单次迁移不同；本期不增加用户自行管理仓库订阅的 bot 命令。

从全局仓库池移除仓库时，清除全部通知目标对该仓库的订阅，并沿用 ADR 0004 停止监控、取消积压及结束共享 Issue 追踪的规则。重新加入仓库开启新的全局监控周期，原个人订阅不恢复，由管理员重新分配，避免形成隐式的自动订阅。

后台以通知目标为编辑入口，在现有列表显示 QQ 号备注、订阅数量和仓库。编辑时从全局仓库池多选，一次保存完整仓库清单，支持仓库搜索、全选和清空，并明确显示空订阅状态；本期不增加按仓库批量分配用户的第二套入口。

保留 ADR 0003 的追踪命令独立授权，`/track` 与 `/untrack` 分别授权。授权用户即使未订阅某仓库，也可以管理该仓库的共享 Issue 追踪，但只有订阅该仓库的通知目标接收其动态；不引入个人追踪清单。

本文记录用户已确认并授权实施的设计；实现以本地仓库订阅规格与四张工单为验收依据。
