# 移除终止仓库监控，重新加入开启新周期

重新加入监控仓库从加入生效时间开始，仅通知此后创建的 Issue，不自动补发停监期间的 Issue。移除取消该仓库尚未发送及等待重试的通知投递，并停止其单独 Issue 跟踪及相关未发送投递；保留历史发现与已发送记录用于去重。已提交给 QQ API 的请求可能完成，无法撤回。

这替换配置热加载设计中“删除保留队列、重新加入恢复原进度”的规则。恢复旧进度虽然避免漏掉停监期间的 Issue，却会使重新加入触发大量历史通知；选择新监控周期，使移除和重新加入符合使用者的停止与重新开始预期。不提供补发历史入口。

移除生效意味着该仓库已禁止新发送、旧投递已取消、单独 Issue 跟踪已停止；配置保存与移除生效分开呈现。发送开始与移除生效必须协调，已开始的 QQ 请求仍可能到达。

首次升级保留当前配置中仓库的既有进度，将配置外的仓库停用并取消未发送投递，避免误取消其他仓库的正常积压。服务没有观察到的中间配置变化无法识别：停机时删除又加回同一仓库，按最终配置视为连续监控。修复覆盖新建 Issue 广播和共享 Issue 跟踪。
