# 直播订阅控制共享直播间监控的生命周期

Bilibili 直播订阅沿用现有 QQ 私聊通知目标，但允许用户通过命令直接订阅任意有效直播间，后台管理同一份关系。一个直播间由全部订阅者共享查询，第一个订阅者加入时开始监控，最后一个订阅者退出后停止查询，以避免为无人接收的直播间持续请求外部接口；代价是不保留无人订阅期间的完整开播历史。

这与 ADR 0005 的全局仓库池明确分离：直播间不要求管理员预先添加，个人直播订阅控制监控生命周期；GitHub 仓库仍保持无人订阅也监控的既有行为。直播自助订阅不扩展仓库命令权限。直播通知沿用发现时确定接收者、逐接收者持久化投递和退订取消未完成投递的原则。

用户已逐项确认这些决策，并通过 to-spec 要求综合发布正式规格；本地 Bilibili 开播通知规格已标记为 ready-for-agent，测试范围也已确认。后续用户通过 implement 授权实施，五张工单已实现并完成双轴复审；尚未部署线上。
